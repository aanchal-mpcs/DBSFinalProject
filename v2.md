# UChiSchedule v2 Updates

## update1_2026-04-29

This update summarizes the work completed since the last git push.

### Registration flow improvements

- Added a shared UChicago registration URL that points directly to the course search / registration page:
  - `https://coursesearch92.ais.uchicago.edu/psc/prd92guest/EMPLOYEE/HRMS/c/UC_STUDENT_RECORDS_FL.UC_CLASS_SEARCH_FL.GBL`
- Replaced the older `my.UChicago` registration links in the popup and calendar with this direct registration entry point.
- Added `Register` buttons to the course action area on catalog pages so students can jump to registration while reviewing a class.

### Calendar page course actions

- Added per-course action buttons in the calendar sidebar for each saved course.
- Each saved course on the calendar page now includes:
  - `Feedback`
  - `Register`
  - `Description` when a course detail URL exists
- This makes the calendar page more actionable, since students no longer need to return to the catalog page to open those related course links.

### Conflict styling updates

- Refined the way conflicting classes appear in the weekly calendar.
- Conflicting course blocks are now:
  - more translucent
  - overlaid with darker diagonal gray stripes
- This makes schedule conflicts stand out more clearly while still keeping the underlying course block readable.

### Notes

- These changes were checkpointed locally in commit:
  - `090914f` `Add registration actions and refine conflict styling`

## update2_2026-04-30

## update3_2026-05-03

This update summarizes the merged work integrated into the main local base branch on May 3.

### Registration handoff improvements

- Reworked `Register` so it no longer only opens the UChicago registration page.
- Register actions now:
  - copy the most useful course registration text first
  - then open the registration page
  - show lightweight temporary feedback such as `Copied Course`, `Copied 3 Courses`, or `Opened Registration`
- This behavior now exists across the main extension surfaces:
  - content-script course actions
  - popup course cards
  - calendar sidebar course cards
  - calendar-level register button

### Storage hardening and schedule-name behavior

- Added a normalization / migration pass when loading saved data from `chrome.storage.local`.
- Stored data is now repaired more safely when fields are missing or malformed, including:
  - missing schedule objects
  - missing schedule ids
  - missing schedule names
  - missing course maps
  - invalid active schedule indexes
- Generic auto-managed schedule names now recompute more consistently after schedule mutations.
- Quarter-based names like `Spring 2026` are preserved when appropriate, while manual schedule names are not overwritten.

### Integrated UI consistency updates

- Applied selected low-risk UI-polish changes from the parallel UI branch without taking the full branch wholesale.
- Updated labels for better consistency, including:
  - `Feedback` instead of `Course Feedback`
  - `Description` instead of `Full Description`
- Improved button-style consistency so:
  - `Register` is more consistently teal
  - `Open Calendar` is more consistently maroon
  - description links use a more consistent outlined treatment
- After testing the alternate wording, the original labels were restored where they felt stronger:
  - `+ Calendar` was kept instead of `Add to Calendar`
  - `See My Calendar` was kept instead of `Open Calendar` on the injected catalog-page button
